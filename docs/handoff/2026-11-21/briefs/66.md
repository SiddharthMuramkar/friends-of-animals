## Scope

**66a**
- **ErrorReporter port.** A Sentry adapter (`@sentry/nextjs`, exact pin; check its Next 16.4 support in the package docs) and an in-memory fake registered through 57a's registry.
- **Wiring.** Server init in `src/instrumentation.ts` with `onRequestError`, plus client init.
- **Scrubber.** `sendDefaultPii: false` and a `beforeSend` / `beforeBreadcrumb` scrubber that:
  - drops request bodies, cookies, auth headers and query strings;
  - keeps only a hashed user id;
  - redacts emails, Indian phone numbers (`+91` and 10-digit) and known name fields from messages, breadcrumbs and `extra`.
- **Defaults.** The `environment` tag is `APP_ENV`. With no DSN the reporter does nothing, and the build still needs no secrets.
- **CSP.** An optional same-origin tunnel route, so 65's `connect-src` stays `'self'`.

**66b**
- `@sentry/node` in the worker.
- `worker_heartbeat` freshness in `/api/health`, which returns 503 when stale. The table comes from 61b; whichever lands first owns it.
- Uptime check definitions and the logging setup: a Vercel log drain and VPS container logs shipped to a 365-day store.
- `docker/README.md`: every check, where alerts go, and how to silence them.

## Acceptance criteria as testable checks

1. **A test error on staging appears in Sentry, tagged with the environment** (unit + residue HR-22/HR-27).
   - With the fake reporter, a thrown error in a route produces one event with `environment === APP_ENV`.
   - The real event on staging is the owner's check after the DSN is set and M0 → main.
2. **No personal data in Sentry events** (unit).
   - A fake event carrying a fake email, `+91 98xxxxxxxx`, a name field, cookies, an auth header, a request body and a `?email=` query comes out of the scrubber with none of them.
   - The user is reduced to a hashed id.
   - A snapshot of the scrubbed event is the oracle.
3. **Uptime checks for the app, the pooler and the worker, and a forced failure alerts** (seam1 + residue HR-23).
   - `/api/health` returns 200 with a fresh heartbeat. After `clock.advance` past the threshold it returns 503 with `Cache-Control: no-store`.
   - The checks for `/api/health`, TCP `db.shipped-it.dev:6432` and the heartbeat, and the forced alert, are the owner's.
4. **Logs kept ≥ 365 days, storage documented** (evidence + residue HR-24). `docker/README.md` names the store, its retention setting and how Vercel and VPS logs get there; the `docker/compose.yml` logging driver ships container logs (the old `json-file` 50 MB × 5 can't hold a year). Creating the store is the owner's job.
5. **README lists each check, where alerts go, and how to silence them** (evidence, 66b). A section in `docker/README.md` with one row per check.

Boilerplate on top: with no DSN the reporter does nothing (unit); `DATABASE_URL= DIRECT_URL= APP_ENV=local pnpm build && pnpm check:build` passes with no Sentry token, public pages stay prerendered and the client bundle stays within 170 kB; no personal data in logs.
