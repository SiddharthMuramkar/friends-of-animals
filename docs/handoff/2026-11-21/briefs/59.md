## Scope

**59a**
- **Roles.** An enum `role` with the 16 roles from #55, an enum `role_scope_type` (global, institution, competition, organisation), and a `user_role` table: `scope_id` is a uuid with no FK, null exactly when the scope is global; unique on (user, role, scope type, scope id) with `NULLS NOT DISTINCT`; records who granted it and when.
- **Policy.** `can(actor, action, resource)` replaces the **internals** of 57a's stub, never its call sites. Roles load per request, with no cache.
- **Use cases.** `grantRole`, `revokeRole`, `searchUsers` and `searchAuditLog`.
- **Audit.** An `audit_log` table (actor, role, action, entity, before/after jsonb, IP, user agent, time) and an `AuditLog.write(tx, …)` helper every later use case calls.
- **Custom SQL.** A trigger function that rejects UPDATE and DELETE on each row, plus a TRUNCATE statement trigger.
- **Seed.** Users with several roles and scopes, using fixed `SEED_IDS` for scopes that don't exist yet.
- **Ops.** The `pnpm admin:bootstrap-super-admin --email` script; the owner runs it against production (HR-18).

**59b**
- `/admin/roles`: find a user, grant or revoke a scoped role.
- `/admin/audit`: search by user, entity type and action, with pages.
- `/dashboard`: role switcher for users with several roles.
- The `(staff)` admin layout, which #60 gates later.
- The Seam 2 journey `tests/e2e/59-roles.spec.ts`, and axe on all three pages.

## Acceptance criteria as testable checks

1. **Grant and revoke take effect at once** (seam1).
   - `as(superAdmin).grantRole({ userId, role: "institution_coordinator", scope: { type: "institution", id } })`, then the grantee's **next** `as(...)` call passes `can(…, that institution)`.
   - After `revokeRole` the same call is refused, with no re-sign-in.
2. **Only a super admin manages roles** (seam1). `grantRole` and `revokeRole` called as `staff_admin` and as `member` both fail with `forbidden`, and no `user_role` or `audit_log` row is written.
3. **Audit row per change** (seam1). Each grant or revoke writes exactly one `audit_log` row with the action, `entity_type='user_role'`, `before` (null for a grant) and `after` (null for a revoke), the actor id, and the IP and user agent from the actor's request meta.
4. **Append-only at the database** (seam1, raw SQL on PGlite). `update audit_log …`, `delete from audit_log …` and `truncate audit_log` each raise an error, and the row count doesn't change.
5. **Audit search** (seam1). `searchAuditLog` filters by user, by entity type and by action (each alone and combined), newest first, with pagination. A non-admin is refused.
6. **`can()` table** (seam1, table-driven). A global role passes for any scope id; a scoped role passes for its own scope id and fails for another id of the same type (**scope mismatch**) and for a different scope type; a visitor fails everything.
7. **Seed** (seam1). `seedPreview` run twice yields the same users. At least one of them holds 2 or more roles across global and institution scopes, and the super admin exists.
8. **Seam 2 journey** (seam2, 59b). In `tests/e2e/59-roles.spec.ts` the seeded super admin signs in with a mailbox code, opens `/admin/roles`, grants a seeded member `institution_coordinator` for a seeded institution id, and sees the role listed and the matching row in `/admin/audit`. Green on `next start` port 3100 now; `deferred` on the preview until HR-01 and the database are back.
9. **axe** (59b). `expectRendersAccessibly` passes on `/admin/roles`, `/admin/audit` and `/dashboard`, in light and dark.

Boilerplate on top: allow and deny authorization tests per new use case; a user switches dashboards from one account (seam1 plus the journey); audit `before`/`after` store ids and changed fields, not whole personal records (erasure, HR-30); IP and user agent in the data inventory.
