**Not in scope:** HSTS, frame, referrer and the other headers (#50, already in `security-headers.ts`). CSP only, through the **one** `headers()`.

## Scope

- **Static public pages** get a CSP **without** nonces and stay prerendered.
  - Next's App Router emits inline flight scripts (`self.__next_f.push`), so plain `script-src 'self'` breaks hydration.
  - Pick one: per-page hashes, `experimental.sri` with `'strict-dynamic'`, or `'unsafe-inline'` on static pages only. State the choice and the primary source in the PR.
- **Signed-in areas** (`SIGNED_IN_PREFIXES` from 57b's route registry) get a strict nonce CSP set in `src/proxy.ts`, with `x-nonce` passed through.
  - The Next 16.4 guide (`node_modules/next/dist/docs/01-app/02-guides/content-security-policy.md`, line ~397) says **"Partial Prerendering (PPR) is incompatible with nonce-based CSP"**. With `cacheComponents` on, signed-in trees must render fully dynamically (for example `await connection()` in their layout).
- **The inline theme script** in `src/app/layout.tsx` (line 68: `<script dangerouslySetInnerHTML={{ __html: themeScript }} />`) moves to a self-hosted file or gets a build-time hash. JSON-LD blocks are data and aren't affected.
- **Reports:**
  - `/api/csp-report` accepts `application/csp-report` and `application/reports+json`;
  - strips the query and fragment from every URL and drops script samples;
  - caps the body size and stores no IP;
  - plus a `Reporting-Endpoints` header.
- **Rollout:** Report-Only first, then enforce (N days is open in HR-19).
- **Policy builder:** `src/lib/csp.ts` builds the policies from typed directive sets, so 63a (R2), 66a (Sentry), 77b (Razorpay) and 118 (Umami) can add sources without rewriting it.

## Acceptance criteria as testable checks

1. **Public pages: CSP with no nonce, still static** (evidence + seam2).
   - `DATABASE_URL= DIRECT_URL= APP_ENV=local pnpm build && pnpm check:build` shows every public route still ○ or ◐, the same as on M0 today.
   - `check:build` passes its new CSP assertions.
   - `curl -sI http://127.0.0.1:3100/` on `next start` shows `content-security-policy` (or the `-report-only` header) with no `nonce-`.
2. **Signed-in pages: strict nonce CSP** (seam2 + unit).
   - `/account/sessions` (or 57b's signed-in page) sends `script-src 'nonce-<n>' 'strict-dynamic'`, and `<n>` equals the `x-nonce` the page rendered with.
   - Two requests get two different nonces (unit test on the proxy helper).
3. **No violations on staging during the smoke and sign-in journeys** (seam2 locally now; staging part = residue HR-27).
   - A `securitypolicyviolation` and console listener records **0** events across `smoke.spec.ts` and 57b's sign-in journey on port 3100.
   - The staging run happens after M0 → main.
4. **Inline scripts and handlers removed or moved** (evidence + unit).
   - `grep -rn "dangerouslySetInnerHTML" src/app src/components` finds no executable script, only JSON-LD.
   - No `on[a-z]+=` string attributes appear in the rendered public HTML (check-build assertion).
5. **Reports collected without personal data** (unit).
   - Posting a report whose `document-uri` has `?email=x@example.test#frag` and a `script-sample` stores or logs the URL with no query or fragment, and no sample.
   - A body over the cap gets 413.
   - Both content types are accepted.
6. **Header tests** (unit + seam2). One test asserts the CSP on a public page (`/`) and one on a signed-in page, both as unit tests on `csp.ts` and as Playwright header checks in `65-csp.spec.ts`.

Boilerplate on top:

- axe isn't needed, since there are no new pages (the smoke suite reruns).
