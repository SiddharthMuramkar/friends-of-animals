## Scope

**61a**
- **Outbox.** An `outbox` table (UUIDv7 id, event and aggregate, jsonb payload holding ids, never emails; status `pending`, `dispatched` or `failed`; attempts, `last_error`, `available_at`) and `emit(tx, event)` inside the caller's transaction.
- **Queue.** A `JobQueue` port: a pg-boss adapter for the worker and an in-process adapter for Seam 1.
- **Relay and retries.** A relay with retry and backoff that ends in a visible `failed` state.
- **Harness.** `world.drain()` registers its drainer through 57a's registry.
- **First consumer.** Sign-up emits `identity.user_signed_up`, and the worker sends the welcome email through 57a's email port.
- **Same transaction (F8f).** Better Auth creates users outside FOA's transactions. Prove which mechanism keeps the outbox row atomic with the user row: a BA hook sharing the transaction, an `AFTER INSERT ON "user"` trigger (custom SQL), or FOA-owned user creation. Record the reason in the PR.
- **Schedules.** A `SCHEDULES` registry with no entries yet.
- **Recommended shape:** Vercel writes outbox rows only and never touches the `pgboss` schema, because the app roles are DML-only (F6).

**61b**
- `src/worker/main.ts`: relay, pg-boss workers, schedules, and a heartbeat into a `worker_heartbeat` table shared with #66.
- A `Dockerfile` target `worker` and `docker/workers.yml` with `worker-prod`, `worker-staging` and `worker-preview`. `worker-preview` polls pg-nonprod for databases whose comment starts `foa-preview `, runs one relay per database with 1–2 connections, and stops serving a database on `3D000` or when it disappears.
- `pnpm worker:dev` for local work.
- Bootstrap SQL for the roles `foa_worker`, `staging_worker` and `nonprod_worker`, each owning schema `pgboss`.
- A `docker/scripts/preview-dropped.d/` hook.
- `docker/README.md` sections for run, restart and logs.

## Acceptance criteria as testable checks

1. **Welcome event in the same transaction** (seam1). Visitor sign-up writes exactly one `outbox` row `identity.user_signed_up` with `aggregate_id` = the new user id, committed with the user row, no email in the payload. After `await world.drain()`, `fakes.email.lastTo(email)` is the welcome message.
2. **Rollback sends nothing** (seam1). A use case that throws after `emit` (inside its transaction) leaves 0 outbox rows. After `drain()`, `fakes.email.sent` has no welcome message.
3. **Retry with backoff, then visibly failed** (seam1, fake clock).
   - With `fakes.email.failNext(2)`: drain, advance past the backoff, drain, advance, drain. The message goes out on attempt 3.
   - With an always-failing email: the row ends `status='failed'` with `last_error` set, and it appears in the failed-jobs list.
   - Draining twice sends once (the outbox id is the idempotency key).
4. **Staging and preview workers on the VPS in the health checks** (evidence + residue HR-07). `docker compose -f docker/workers.yml config` is valid and every service has a `healthcheck`; on the VPS the owner sees `worker-staging` and `worker-preview` healthy in `docker compose ps`.
5. **Preview DB attach and detach** (seam1 + residue). A pure discovery function over `(datname, comment)` returns only `foa_pr_<n>` databases; a simulated `3D000` or disappearance stops serving that database; on the VPS the owner confirms a new PR is served and dropped after the sweep.
6. **In-process drain** (evidence). `world.drain()` exists. The welcome-email test uses it, with no sleeps and no real pg-boss.
7. **Docs** (evidence). `docker/README.md` has run, restart and `docker compose logs` commands for each worker service.

Boilerplate on top: an outbox row per new event in the same transaction; no personal data in payloads or logs; `pnpm build` with empty database URLs still passes (the worker isn't in the Next build); the pg-boss adapter contract test runs on PGlite if pg-boss works there, else as `pnpm test:pg` on local Postgres 16, outside `pnpm test`.
