## Scope

- **Phone sign-up and sign-in.** Request a code by phone, verify it, get the same session as email. A user with both an email and a phone can sign in with either; both resolve to one user id.
- **SMS port.** An MSG91 adapter for production, a capture adapter outside production (`captured_message` with `channel='sms'`, which 57a creates) and an in-memory fake.
- **SMS switch.** `sms.enabled` defaults to **off**. #62 doesn't exist yet, so add the typed settings accessor stub `settings.get("sms.enabled")` with its code default; #62 binds it to the table later. While it's off, nothing is sent and the UI points to email.
- **Encrypted phone.** The phone is stored encrypted: introduce the reusable Drizzle custom type `encryptedText()` (AES-256-GCM, versioned key ring), which M1 reuses for DOB, address, guardian details and PAN. Lookup uses a keyed blind index (HMAC-SHA-256 of the E.164-normalised number) behind a unique partial index.
- **Limits.** Per-phone and per-IP limits through 57b's Postgres limiter, with a new scope `phone`.
- **Better Auth gotchas (issues-M0 F8e).** BA's `phoneNumber` plugin wants a plain `phoneNumber` column and passes the raw number around. BA's user model also needs a unique email. Pick the design (adapted plugin, custom FOA plugin, or a shared FOA OTP service) and record the reason in the PR.

## Acceptance criteria as testable checks

1. **SMS on, phone sign-up and sign-in** (seam1).
   - With `sms.enabled=true`, `as(visitor).requestPhoneCode({ phone })` puts one message in `fakes.sms.sent` with a 6-digit code.
   - `verifyPhoneCode` with that code returns a signed-in actor and a new user.
   - Repeating the flow for the same phone returns the **same** user id.
2. **SMS off** (seam1 + axe).
   - With the default `sms.enabled=false`, `requestPhoneCode` fails with `DomainError` `sms_disabled` and `fakes.sms.sent` stays empty.
   - `/sign-in` and `/sign-up` show the "codes come by email" notice, and pass axe in that state and with the phone option visible.
3. **Encrypted at rest** (seam1, raw SQL on PGlite).
   - `select * from "user"` contains neither the E.164 number nor its 10-digit national part.
   - Sign-in still finds the user through the blind index.
   - `+91 98…`, `098…` and `98…` resolve to one user.
   - Values written with key v1 still decrypt after a v2 key is added.
4. **Rate limits** (seam1, fake clock).
   - The 6th code request for one phone within 15 min fails `rate_limited` with `retryAfter`, and `fakes.sms.sent` has exactly 5 messages.
   - The 21st request from one IP across different phones is refused.
   - After `clock.advance({ minutes: 15 })` requests are allowed again.
5. **No real SMS outside production** (seam1).
   - Adapter matrix: `APP_ENV` local, preview and staging select the capture adapter (a row with `channel='sms'`); production selects MSG91.
   - The env schema rejects a production config without MSG91 keys.
   - No test makes a network call.
6. **Test coverage** (evidence). Seam 1 tests for phone sign-up, sign-in, both limits and SMS off exist under the identity module and use `createWorld`, `fakes.sms` and the fake clock. `pnpm test` is green.
7. **Seed** (seam1). `seedPreview` run twice creates one user with a phone, and that user signs in by phone at Seam 1 with SMS on.

Boilerplate on top:
- allow and deny authorization tests per new use case;
- the phone in the data inventory with its retention;
- every string from `auth.json`;
- `DATABASE_URL= DIRECT_URL= APP_ENV=local pnpm build && pnpm check:build` keeps the public pages prerendered.
- Seam 2: none required, because SMS is off on previews.
